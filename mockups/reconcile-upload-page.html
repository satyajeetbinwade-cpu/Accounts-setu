Design B — the upload page: every state, and what triggers what

A row per file. Choosing a file does the same job the old Upload & normalize button did, in one action.

Choosing a file = upload + normalize. Every path that picks a file — a row's Choose file, Replace, Try again, Add it anyway, or a row's Normalize it now — does the whole pipeline in one go: save it to <client>/<period>/<document>, detect the layout, classify it, map the columns and cache the result. Then the row reports the verdict. There is no separate upload button anywhere.

Mockup, not the live app. Wording matches the real verdicts in setu/state/reconcile_state.py (not_ingested, wrong, partial, review, ok); the 70% bar is AUTO_FILE_CONFIDENCE_THRESHOLD.
